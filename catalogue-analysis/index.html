How we did this

Full transparency on sources, definitions and limits — nothing here is a black box.

Data source

Every published post on vitalcitynyc.org, pulled from the Ghost Content API and mirrored to data/catalogue.json; author bios and post counts from the Ghost authors endpoint (data/authors.json). This page reads the pre-aggregated data/catalogue_analysis.json, recomputed by analyze_catalogue.py on each catalogue refresh. Counts reflect the pull stamped at top right.

Key definitions

  • Format is Vital City's own content type (opinion/commentary, Q&A, data analysis, map/tool, book review), inferred by the catalogue pipeline from each post's structure.
  • Subject uses the topic tags attached to each post in Ghost. A post can carry several topics, so topic counts sum to more than the number of pieces.
  • Contributor background is a single label per piece, applied to the piece's primary author. It is assigned by an automated reading of the author's bio: the first professional role named in the bio wins (bios are written "is a [main role] and…"), with a short hand-checked override list for the most prolific contributors. It is an approximate heuristic, not a hand-verified label for all 472 authors.

Limitations worth keeping in mind

  • 2021 and 2026 are partial years. Vital City launched in September 2021, and 2026 runs only through the pull date — so those bars are not comparable to full years. They are flagged in the chart.
  • Contributor background is single-label and heuristic. Many contributors hold several credentials at once — a former prosecutor who now teaches law, a reporter who runs a nonprofit. We assign the role the bio leads with. Roughly one in ten pieces lands in "Other / unclassified" (mostly one-time contributors whose bios don't state a clear role) or "Unknown / no bio."
  • The "Vital City (institutional)" slice is pieces bylined to the journal itself (staff-written explainers, surveys, round-ups), not a person.
  • Topic tagging is applied by editors over time and is not perfectly consistent across five years.

Reproducibility

The aggregation is a single stdlib-only script, analyze_catalogue.py, which reads the two JSON inputs and writes the numbers charted here. The credential keyword rules and override list live in that file, commented.
